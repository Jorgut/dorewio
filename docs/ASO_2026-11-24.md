# ASO 核查与 1.1 元数据计划 — 2026-11-24

触发：ASO Scout（Zen Labo Ltd）冷启动邮件，声称 dorewio 的副标题为空、30 个字符没用。

## 结论：邮件的主要说法不成立

通过 App Store Connect API 直接读取当前线上元数据（2026-11-24）：

| 字段 | 实际值 | 长度 |
|---|---|---|
| Title | `dorewio` | 7 / 30 字符 |
| Subtitle（zh-Hans） | `小提琴 · 调音 · 识谱 · 跟奏` | 18 / 30 字符 |
| Keywords（zh-Hans） | `小提琴,调音,音准,识谱,指板,乐谱,跟奏,练琴,节奏,听音` | 72 / 100 字节 |

所以不存在「副标题空着、浪费 30 字符」的问题。

ASO Scout 报告显示 `Subtitle 0/30` 的原因很可能是：它读取的是 **US storefront**，而 dorewio 只有 `zh-Hans` 一个本地化，没有 `en-US`；它的解析没有回退到 zh-Hans 元数据。报告里的 Impressions / Downloads 也标注为 **Example**，不是我们的真实数据。

## 仍有优化空间（不是 bug）

- 副标题还有 12 个字符余量，可加入「自学」「节拍器」这类高意图词。
- 关键词还有 28 字节余量，可加入「入门」「零基础」「陪练」「五线谱」「考级」等，但不要重复副标题已有的词。
- 标题 7/30 是品牌选择，不是错误；暂不建议为了关键词把标题堆长。

## 1.1 建议元数据（待确认后写入 ASC）

保守方案（保持标题品牌）：

- Title：`dorewio`
- Subtitle（21 字符）：
  `小提琴自学 · 调音 · 识谱 · 节拍器`
- Keywords（82 字节）：
  `入门,零基础,陪练,音准,五线谱,琴谱,考级,揉弦,运弓,指板,听音`

不选「把 23 个字符全塞进标题」：标题同时是主屏幕名称，堆词会截断且显得像马甲包；先改副标题/关键词，观察 2–4 周。

## 验收方式

1. 1.1 提审时在 ASC → App Information 改 Subtitle，在版本本地化改 Keywords。
2. 生效后看 ASC Analytics：搜索展示次数 → 产品页浏览 → 下载，对比改动前 28 天。
3. 若 4 周后搜索展示仍低，再测试标题 `dorewio · 小提琴自学`（15 字符），不要与副标题同时改，否则无法归因。
4. 搜索结果前 3 张截图应直接表达「小提琴自学 / 调音」，不要先放训练列表。
